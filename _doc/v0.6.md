# SMS4 v0.6 — 私訊流程重構（規劃草案）

將私訊的入口從 Messages 頁面內建的使用者列表與「新訊息」彈窗，改為透過「使用者」頁面搜尋 → 進入使用者專區 → 點選「傳送訊息」按鈕。

---

## 1. 問題描述

原本 Messages 頁面同時包含：
- 使用者切換列（所有使用者）
- 對話紀錄列表（曾傳過訊息者）
- 「新訊息」按鈕 + 全使用者彈窗

這造成 UX 混淆：使用者列表出現在私訊頁中，但又不直接顯示對話。若要發送新訊息，必須點「新訊息」再從另一個使用者清單選取。

---

## 2. 修改後的流程

### 新訊息流程

```
使用者 → 搜尋使用者 → 進入使用者專區 → 點擊「傳送訊息」按鈕 → 進入對話頁
```

### 私訊頁面

Messages 頁面只顯示**曾傳過訊息的朋友列表**（對話紀錄），點選後進入對話頁。不再顯示「新訊息」按鈕與使用者切換列。

---

## 3. 前端修改

### Messages.tsx

| 項目 | 修改前 | 修改後 |
|------|--------|--------|
| 使用者切換列 | 頂部橫向捲動所有使用者頭像/名稱 | **移除** |
| 新訊息按鈕 + 彈窗 | 右上角「新訊息」→ 全使用者清單彈窗 | **移除** |
| 對話列表 | 依 currentUserId API 回傳 | **保留**（唯一內容） |
| 空狀態文案 | 「尚無對話」+「點擊新訊息開始聊天」 | 「尚無對話」+「前往使用者頁面搜尋並傳送訊息」 |

### UserDetail.tsx

| 項目 | 修改前 | 修改後 |
|------|--------|--------|
| 操作按鈕 | 僅「追蹤/追蹤中」 | 「傳送訊息」+「追蹤/追蹤中」 |
| 傳送訊息行為 | 無 | 導航至 `/messages/:userId?uid=:currentUserId` |


---

## 5. UX 原則

- **單一職責**：Messages 頁面只處理「已有對話」的檢視；發起新對話從使用者頁面開始
- **自然動線**：使用者頁面已有搜尋功能，找到目標使用者後直接私訊是直覺操作
- **減少干擾**：移除不必要的使用者切換列，減少資訊密度
